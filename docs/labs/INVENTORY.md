## Status meanings and evidence limits

**Real** means a source-traced end-to-end path to an actual local engine or
persistent operation exists for the stated function. This is a code assessment,
not an executed live deployment/hardware/credential check. A mere route or type
export is not evidence that an external operation completed.
**Needs a key** means a production provider needs configuration/authorization.
**Sample** means invented demo data, synthetic audio or a deterministic fallback.
**Stub** means a recorded plan/pending handoff or an unavailable counterpart,
not completed audio processing or delivery. One surface can contain multiple
statuses; the exceptions below override the generic source registry.

The owner identifies the labs preview as https://street-banker-labs-staging.onrender.com,
built from main in practice mode. Motion staging uses motion-vault and live uses
motion-live. These deployment facts are owner-supplied; no Render settings were
queried or changed. Neither Motion branch is a target of this job.

## Hash routing and API boundary

`apps/web/src/App.tsx:42` parses hashes. Song project URLs use
`#/song-lab/projects/:id/:tab`; Studio uses `#/studio/:id/:tab` with an allowlist
and Session fallback; Live uses `#/live-lab`, settings, project, performance and
MIDI paths. `set`, `audio` and `ai-scenes` are workspace areas, not separate pages.
Song unknown tabs must be evaluated against its rendered fallback in migration.
`navigate` changes the hash (`App.tsx:102`). These are not server path routes.
Fastify registers all three API modules in `apps/api/src/server.ts`, with existing
session/organization, entitlement, CSRF and rate-limit boundaries. This repo's
cookie auth is not itself the live Motion SSO adapter. Motion already uses the V1 handoff on
`motion-live`: `packages/auth/src/suite-sso.ts`, blob
`75705ed21a4245459c5870dce6e9c3fc49360d5b`, verifies the Python
`sb_suite_sso.py` wire contract and 120-second suite-bound token, and signs Vault
proofs. Reuse that boundary after reviewing current main and permissions; do not
replace live Motion or invent another login.

## Feature, ease-of-use and graphic audit

The useful foundation is evidence-based findings, human correction, immutable
versions and recoverable local playback. The present navigation exposes internal
subsystems before the artist has a clear next action. Repeated import/version
surfaces and broad “release” terminology obscure where bytes actually live.
Small 11px helper text exists in Live; native dense tables and many simultaneous
actions need a phone-first redesign. Status must distinguish measured output,
synthetic content, missing configuration and pending downstream work.

Recommend one pinned song/version identity, one next action, six progressive
steps, a result receipt after every handoff, and evidence expanded on demand.
Use black/off-white surfaces with restrained gold for hierarchy and primary
actions, sentence case, a readable sans-serif, calm spacing and a compact
reusable section-help pattern. Preserve emergency actions as large, explicit
controls. Do not apply the combined suite shell to mid-show performance until
device-level tests pass. See DESIGN.md and BUILD-PLAN.md for the approval gates.
