# Live Lab

Live Lab (the Street Banker live-performance module) turns an artist's existing
release assets, stems, and authorized AI-generated material into a stage-ready,
MIDI-controlled live show. It is **show construction and control** — not a DAW,
and deliberately so: no piano roll, no multitrack recording, no plugin hosting,
no automation lanes.

The one-line contract: **current playback never depends on the cloud.**

## Where things live

```
packages/performance-project   shared vocabulary: records, manifest, capabilities,
                               Stage Control interfaces (zod-validated)
packages/live-engine           the performance core: tempo clock, quantization,
                               transport, scenes, stems, click, crash recovery,
                               Web Audio + AudioWorklet backend, test backend
packages/midi-engine           MIDI parsing, MIDI Learn, mapping application,
                               Web MIDI + mock device sources
packages/performance-cache     local package cache: IndexedDB + memory stores,
                               checksum verification
packages/ai-audio              provider-agnostic AI audio layer: prompt safety,
                               mock provider that synthesizes real WAVs
apps/api/src/routes/live-lab.ts  the HTTP surface (org-scoped, entitlement-checked)
apps/web/src/live/             home, workspace, Performance Mode, MIDI settings
packages/domain/src/live-lab.ts     persistence (LiveLabRepo)
packages/domain/src/entitlements.ts EntitlementService (Partner OS seam)
packages/runtime/src/live-lab.ts    LiveLabService: AI job execution, package build
```

The engine packages have **no dependency on React, Fastify, or the database** —
that is the isolation that lets `apps/desktop-live` reuse them unchanged (see
[LIVE_LAB_DESKTOP.md](LIVE_LAB_DESKTOP.md)).

## Concepts

| Concept | Meaning |
|---|---|
| Live project | One show/set. Org-scoped. Carries master tempo, time signature, 16-pad map. |
| Set item | One entry in the setlist: song, walk-on, interlude, encore, outro. |
| Scene | A launchable section of a song (INTRO, VERSE, DROP, …) with quantization, loop, follow action. |
| Clip | Audio inside a scene, referencing a live asset (start/end/loop points, gain, pan). |
| Stem | A per-song continuous layer (VOCAL/DRUMS/BASS/MUSIC/FX/CLICK + custom) with mute/solo/volume/pan. |
| Live asset | An audio file the org owns: uploaded, imported, or generated. Rights status recorded. |
| Performance package | The verified offline bundle a show runs from. See [LIVE_LAB_OFFLINE.md](LIVE_LAB_OFFLINE.md). |

## Routes (web)

```
#/live-lab                          home: BUILD MY LIVE SET + recent projects
#/live-lab/projects/:id             workspace: setlist · scenes · pads · stems · AI builder · set builder
#/live-lab/projects/:id/performance Performance Mode (full-screen stage surface)
#/live-lab/projects/:id/midi        MIDI devices, Learn, mappings, keyboard zones
#/live-lab/settings                 entitlements report · audio output device · cue/click levels · storage
```

The nav entry appears only when the organization holds `live_lab.access` — and
the server enforces every capability regardless of what the UI shows.

## Entitlements

Capabilities (see `packages/performance-project/src/capabilities.ts`):
`live_lab.access`, `.projects`, `.stems`, `.midi`, `.performance_mode`,
`.offline_cache`, `.ai_scene_builder`, `.remix_import`, `.multi_output`,
`.stage_control`, `.desktop`, `.api` — plus numeric limits
(`live_lab.max_projects`, `.max_ai_generations_per_month`, `.max_package_bytes`, …).

The bootstrap (flagship) organization gets the full set at signup and at seed.
Partner/white-label orgs are provisioned with a subset via `EntitlementService`.
Enforcement is server-side in every route; limits are checked where the limited
resource is created.

## Demo

`pnpm seed` creates **Example Artist — Demo Set**: a 7-item setlist (WALK ON →
OUTRO), scenes with locally synthesized clips, VOCAL/DRUMS/BASS/MUSIC/CLICK
stems per song, a populated 16-pad map, and a mock-controller MIDI mapping.
Every audio file is generated by `@masterclip/ai-audio`'s synthesizer — no
copyrighted material anywhere in seed data.

## Status by phase

- **Phase 1 (MVP)** — built: projects, setlist, scenes, clip launcher, 16-pad
  grid, stem deck, Web Audio engine + AudioWorklet click, BPM + quantization,
  MIDI Learn + mappings, local cache, performance package + verification,
  Performance Mode, crash recovery, stereo output, demo project, tests.
- **Phase 2 (integration)** — built: release import, stem import, Remix-style
  asset import between live projects, AI Scene Builder on the provider layer
  (mock provider), usage ledger entries, Stage Control handoff, entitlements.
- **Phase 3 (advanced)** — largely built: output abstraction with cue/click
  buses and whole-mix output-device selection (`AudioContext.setSinkId` where
  supported), per-stem meters, scene follow actions, background generation, and
  the **Live Set Builder** (`POST /projects/:id/build-set`): server-computed
  suggestions — walk-on, interlude, encore, outro, click tracks for songs
  missing them, a default pad mapping — each requiring explicit approval before
  anything is added, and never touching existing items or masters. Per-stem
  *device* routing, the keyboard sampler and custom macros remain desktop-phase
  work.
- **Phase 4 (desktop)** and **Phase 5 (live AI instrument)** — architecture
  prepared, not built. The experimental NEXT SCENE mode is intentionally not
  enabled; its constraint is already enforced everywhere: generated audio is
  triggerable only after it is fully downloaded, validated and cached.
